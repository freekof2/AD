## 嵌入资源与归档迹象

扫描在文件中发现了 `app.asar` 文本标记，偏移包括 `3,609,342`、`126,126,502`、`142,424,673` 和 `142,424,693`；同时发现 `node_modules` 和 ZIP 局部签名。**这些标记本身不能证明存在一个可直接挂载的 ASAR 文件**，因为它们也可能是字符串、压缩数据或打包器元数据。

使用 7z 对 PE 做只读提取后得到 69 个条目，主要是 `.text`、`.rdata`、`.pdata`、`.rsrc`、图标、清单和证书等 PE 节/资源数据；提取结果中没有自动识别出带 `.asar` 扩展名的独立文件。Electron 官方资料说明 ASAR 是一种带 JSON 索引的、将文件内容串接保存的归档格式，并且应用通常可以直接从 ASAR 虚拟文件系统读取内容。[2] [3] 因此，后续若要继续恢复 JavaScript，应在隔离环境中针对候选偏移做 ASAR 头部与 JSON 索引验证，而不是仅凭字符串命中直接提取。

## 代码恢复结论

由于样本未检测到 CLR/.NET 元数据，本工作流没有调用 .NET 反编译器。当前仓库实现的“反编译工作流”包含以下安全阶段：

1. 校验下载地址、重定向主机和 SHA-256；
2. 解析 PE 头、节表、数据目录和导入表；
3. 提取 ASCII 与 UTF-16LE 字符串，并扫描常见打包/归档标记；
4. 使用 7z 做只读归档提取并生成文件清单；
5. 仅在显式开启 `--decompile` 且检测到 CLR 元数据时调用 `ilspycmd`；
6. 将 `report.json`、`SUMMARY.md` 和 `strings.txt` 上传为 Actions 工件。

这次运行已经完成**静态指纹与资源线索提取**，但没有生成可声称为“完整 C/C++ 源码”的结果。原生 x64 PE 的进一步反编译需要额外接入 Ghidra、IDA 或 Binary Ninja 等原生代码分析器；本仓库当前不执行该类工具的自动安装与深度分析，以避免把未经授权的第三方样本交给更强的代码执行/解析链路。

## 可复现入口

```bash
# 下载并校验发布资产
make fetch

# 静态解析与只读 7z 提取
make analyze

# 仅在明确需要且环境隔离时，尝试可选代码恢复
make decompile
```

GitHub Actions 入口位于 `.github/workflows/static-analysis.yml`，仅支持手动触发。生成的完整工件可从 [运行 31600417094](https://github.com/freekof2/AD/actions/runs/31600417094) 下载。[4]

## 安全与范围边界

本报告不判断样本的恶意性，也不提供绕过授权、破解保护、窃取凭据、规避反分析或进行动态持久化测试的步骤。任何后续动态分析都应使用与宿主机隔离的专用环境、无敏感凭据的临时账户和明确的网络出口策略。
